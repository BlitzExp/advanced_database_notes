## What I understood

Indexes are most useful when they reduce the amount of data Oracle needs to read. A column with many different values, such as `patient_id`, is usually more selective than a column with very few values, such as `site_id` or `status`.

For range queries, the size of the range matters. A query for the last 7 days is much more selective than a query for the last 700 days, so Oracle is more likely to use an index for the smaller range.

Composite indexes depend heavily on column order. An index on `(patient_id, visit_date)` works well when the query filters by `patient_id`, with or without `visit_date`, but it usually does not help much when the query filters only by `visit_date`.

## What is still confusing

- The exact plan may change depending on table size, data distribution, optimizer statistics, and whether the query selects all columns or only indexed columns.
- Oracle can sometimes choose not to use an index even if one exists because a full table scan may be cheaper.
